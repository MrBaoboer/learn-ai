Prompt Harness

Skill: 운영 가능한 Prompt 모듈

System Prompt은 AI가 누구인지를, Tool은 AI가 무엇을 할 수 있는지를 정의합니다. 그렇다면 Skill은 무엇을 담당할까요? 특정 상황에서 어떻게 단계별로 잘 처리할지를 담당합니다. 파일이 곧 설정이며, 버전 추적이 가능합니다.

세 가지 비교

System Prompt

글로벌 정체성
AI가 누구인지 정의합니다: 이름, 성격, 기본 원칙. 모든 대화의 배경입니다.
적용 범위전역
변경 빈도드뭄
라이프사이클전체 제품

Tool

기능 등록
AI에게 사용 가능한 도구를 알려줍니다: 이름, 파라미터, 기능. 기능의 메뉴입니다.
적용 범위단일 호출
변경 빈도보통
라이프사이클기능 반복

Skill

프로세스 가이드
완전한 태스크 실행 방안: 언제 트리거할지, 어떤 도구를 쓸지, 어떤 단계로 진행할지.
적용 범위특정 태스크
변경 빈도고빈도 반복
라이프사이클독립 버전
Skill의 구조

각 블록을 클릭해 설명을 펼치세요

content-creator.skill

트리거 조건 이 Skill을 언제 활성화하는가
사용자가 "글 써줘", "쓰고 싶어", "쓰려고 해" 등의 트리거 단어를 말하면 AI가 자동으로 이 Skill을 로드해 이후 행동을 안내합니다. 매 대화마다 로드되는 것이 아니라, 조건이 매칭될 때만 주입됩니다.
허용된 도구 목록 이 태스크에서 사용 가능한 도구
이 Skill 실행 시 허용되는 도구를 명시적으로 나열합니다. 예: 콘텐츠 창작에서는 web_search, note_read를 허용하지만 file_delete는 허용하지 않습니다. 허용 목록으로 리스크를 제어합니다.
실행 흐름 단계별 진행 방법
처음부터 끝까지 실행 단계를 설명합니다: 요구 확인 → 자료 수집 → 아웃라인 작성 → 단락별 작성 → 전체 다듬기 → 납품. 각 단계에는 분기와 조건 판단이 있을 수 있습니다.
출력 형식 요구사항 최종 결과물의 모습
최종 출력의 형식, 길이, 스타일을 규정합니다. 예: 제목 20자 이내, 단락 명확, 구어체 표현, 마지막에 행동 제안 포함. 매번 일관된 출력 품질을 보장합니다.

왜 System Prompt에 바로 쓰지 않나요?
System Prompt는 전역이라 변경하면 모든 시나리오에 영향을 줍니다. Skill은 필요에 따라 로드되어 특정 시나리오에만 주입되므로 다른 태스크의 행동을 오염시키지 않습니다. 또한 Skill 파일은 독립적으로 버전 관리가 가능해 누가 무엇을 언제 변경했는지 한눈에 알 수 있습니다.
Prompt도 재사용, 반복, 추적이 필요합니다. Skill은 Prompt의 모듈화입니다. 코드를 관리하듯 AI 행동 지침을 관리하세요. 태스크마다 파일 하나, 수정하면 바로 적용됩니다.
