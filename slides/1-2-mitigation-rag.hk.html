SaaS 產品技術支持機器人

PM 決策框架：什麼時候必須上 RAG？
✅
知識時效性強：政策/產品/價格頻繁更新，模型訓練數據趕不上
✅
私有知識庫：公司內部文檔、產品手冊，模型根本沒見過
✅
答錯代價高：法律、醫療、金融場景，錯一句可能引發事故
⚠️
閒聊/創意場景不需要：RAG 反而讓回答更死板

無 RAG：閉卷考試
問題 → × 訓練記憶推斷
前文只有問題本身，模型只能靠訓練數據裏的印象來推 Token
有 RAG：開卷考試
真實文檔片段 + 問題 → ✓ 準確回答
檢索到的文檔成為前文的一部分，直接影響每步 Token 的概率分佈
模型本質是 Token 推 Token，推出什麼取決於前文是什麼。 RAG 就是「用檢索到的真實文檔作為高質素前文」注入上下文： 相同的模型，前文換了，後文的概率分佈就變了。 模型沒有變聰明，只是有了一個更好的起點。
⚠ 侷限性：RAG 不是銀彈
檢索本身可能出錯
檢索召回的文檔片段不準確時，模型會把錯誤文檔當作真實依據，幻覺不但沒減少，還多了一個權威出處的外衣
模型仍會腦補文檔外的內容
檢索到的上下文窗口有限，超出範圍的部分模型仍會用訓練記憶補全，RAG + 幻覺混合輸出，比純幻覺更難被用戶識別
PM 應對策略
RAG 的質素上限 = 知識庫質素。需要建立檢索命中率評測，同時用引用來源強制顯示讓用戶可核查
