思路一 · 先換它能看見的世界，再收緊呼叫
它解決什麼問題

同事在 Mac 上跑 Codex，agent 去讀 ~/.ssh/id_rsa，Seatbelt 立刻回 Operation not permitted。同一份倉庫放到 Linux 筆記本上，常見文案變成 No such file or directory。路徑常常根本不在掛載裡。

如果先開啟 PR_SET_NO_NEW_PRIVS，再去調系統自帶的 bwrap，不少發行版上的 setuid 二進位會直接起不來。沙箱在裝得最全的機器上反而失敗。seccomp 是一套核心過濾器，用來規定程序還能呼叫哪些系統介面；no_new_privs 是它的前置條件，也會擋住 setuid 提權。

思路是什麼

預設路徑兩次進入同一份 helper。外層只拼 bubblewrap，把檔案系統換成預設只讀，再疊可寫根，.git、.agents、.codex 即使落在可寫根裡也保持只讀。內層才開啟 no_new_privs、裝網路 seccomp，然後 fork、把行程映象讓給使用者命令。

函式頭把順序寫成三步：

codex-rs/linux-sandbox/src/linux_run_main.rs第 152 至 158 行
/// Entry point for the Linux sandbox helper.
///
/// The sequence is:
/// 1. When needed, wrap the command with bubblewrap to construct the
///    filesystem view.
/// 2. Apply in-process restrictions (no_new_privs + seccomp).
/// 3. `execvp` into the final command.

教學化結構圖：同一份二進位進兩次，中間隔著 bubblewrap 建好的世界。
為什麼長期成立

能看見什麼，和能呼叫哪些 syscall，是兩道牆。先換世界，再收緊呼叫。換成別的語言重寫，發行版上只要還有 setuid 包裝器，這個順序就還成立。

思路二 · 單獨起 helper，留下一個收孤兒的人
它解決什麼問題

bubblewrap 和 seccomp 必須發生在即將變成使用者命令的那個行程裡。主 CLI 自己 unshare 再 exec，失敗會把整次會話帶走，也沒法在 PID namespace 裡留下一個收孤兒的 1 號程序。超時和取消會留下睡眠行程。

思路是什麼

Linux 看 argv[0] 的 basename。檔名已經是 codex-linux-sandbox 就保留，否則改成這個別名，把同一份二進位拐進 helper。外層 exec 的不是 ls，是 helper 自己，帶著 --apply-seccomp-then-exec。launcher 還會插進 --as-pid-1，讓 bubblewrap 自己當名稱空間裡的 1 號程序。

內層先 capget。effective 或 permitted 任一非零，立刻 panic，命令不會跑。過了這道檢查，才 fork。子行程 execvp，父程序 waitpid(-1) 把子孫都收掉，退出碼原樣傳出。出處：codex-rs/linux-sandbox/src/linux_run_main.rs 第 216 至 221 行、第 242 至 243 行；codex-rs/linux-sandbox/src/launcher.rs 第 38 至 39 行

教學化時序圖：行程讓出去之後，收屍的人還在。
為什麼長期成立

獨立輔助行程加先包裝、再收緊，是跨平臺同一類自我呼叫。Windows 看隱藏參數，Linux 看 arg0。包裝器失敗時，固定退出碼加固定 stderr 前綴更好自動歸因。

思路三 · 預設不是 Landlock，失敗也不回退
它解決什麼問題

型別名還叫 LandlockCommand，crate 目錄也叫 linux-sandbox，網上不少資料會寫成 Codex 在 Linux 上用 Landlock。當前預設檔案系統沙箱已經是 bubblewrap。Landlock 是顯式開啟的 legacy 回退，特性開關標成 Deprecated，預設關。legacy 吃不下受限讀，也吃不下拆分出來的巢狀只讀。

如果 bwrap 失敗後靜默換 Landlock，模型會按「我被關在檢視裡」規劃，實際卻還看得見主機檔案樹。下一步就會分叉。

思路是什麼

外層寫明 never falls back。bubblewrap 失敗就失敗。WSL1 在需要 bubblewrap 時，transform 返回 Wsl1UnsupportedForBubblewrap，命令不會進 helper。全盤可寫且不走代理時，根本不會進 bwrap，WSL1 可以過。user namespace 建不出來給啟動警告，不會改走更弱的後端。出處：codex-rs/linux-sandbox/src/linux_run_main.rs 第 290 至 294 行；codex-rs/sandboxing/src/manager.rs 第 413 至 420 行、第 696 至 710 行；codex-rs/features/src/lib.rs 第 1064 至 1069 行

教學化結構圖：都叫 Linux 沙箱，三臺機器啟用的那一層並不一樣。
看見和呼叫是兩道牆。進不去就明說，不要合成一句已經沙箱了。
為什麼長期成立

跨平臺能力不對等時，最容易犯的錯是用「我們有 Linux 沙箱」覆蓋所有 Linux。本機有新 bwrap、CI 容器禁了 user namespace、同事還在 WSL1，三臺機器不是同一道牆。產品文案和模型說明必須按實際啟用的那一層來寫。

橫向對比 · 三拍拆開之後，各自漏什麼

DeepSeek Harness：探得過就換檔，合成一拍

DSH 的 Linux 鏈寫死為 bwrap 再 landlock。bwrap 檔是檢視加 exec，沒有 seccomp。探不過才走 landlock-run：在自己身上裝規則，再 exec 目標命令。檔案系統限制和 exec 合在同一份 main 裡。這條路徑沒有 setuid bwrap，所以不必把過濾器再拆到下一拍。

兩邊都走獨立輔助行程。DSH 啟動器失敗是 125，還要同時看到 landlock-run: 致命行，更好自動歸因。Codex helper 失敗是 panic 或原樣 wait status。兩條鏈都探失敗，DSH 拒絕裸跑。它可以換探測過的第二檔，換完仍 fail closed。Codex 預設路徑失敗不回退 Landlock。出處：packages/sandbox/sandbox-local/src/index.ts 第 159 至 166 行；native/landlock-run/packages/entry/src/main.c 第 254 至 261 行

Grok：三拍打在 agent 上，失敗可以回退

Grok 的順序和 Codex 同一條工程理由：先讓可能依賴 setuid 的 bwrap 跑完，再在已經進名稱空間的行程裡收緊。差別在主體。Grok 把三拍打在 agent 行程上，命令只繼承結果。檢視是補丁式的 --bind / / 再蓋 deny 路徑，主機樹還在。子行程 spawn 時，若需要限網，才在 pre_exec 裡裝 seccomp。

bwrap exec 失敗且不要求 read-deny 時，它警告一句，回退到 Landlock。內建 Profile 的 apply 失敗記警告並繼續，is_active() 才是真狀態。Codex 外層寫明 never falls back。出處：crates/codegen/xai-grok-shell/src/config/mod.rs 第 1293 至 1320 行；crates/codegen/xai-grok-sandbox/src/lib.rs 第 181 至 192 行
