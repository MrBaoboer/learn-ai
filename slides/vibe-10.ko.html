VIBE CODING 방법론 · 10강

긴 대화 앵커링과 작문 규범

1번째 턴에서 "PostgreSQL 사용"을 말했는데, 30턴째가 되자 AI가 갑자기 SQLite를 제안합니다 — 초기 합의가 컨텍스트 윈도우 밖으로 밀려났기 때문입니다. 이 강에서는 두 가지를 다룹니다: 긴 대화에서 컨텍스트 드리프트를 방지하는 방법, 그리고 AI가 생성하는 글에서 "AI 어조"를 없애는 방법. 두 가지 인터랙티브 데모로 직접 드래그하고 클릭해 보세요.

학습 목표

드리프트 원인 이해

컨텍스트 윈도우 잘라내기와 긴 텍스트 끝부분의 어텐션 감소로 AI가 초기 합의를 잊게 됩니다. 200K Token 모델도 긴 입력의 끝부분에서 실제로 어텐션이 감소합니다.

체크포인트 설정

10턴이 넘으면 중요한 작업 전에 현재 목표와 핵심 제약 조건을 강제로 복술합니다 — 주기적 앵커로 망각에 대항합니다.

AI 어조 제거

"자연스럽고 유창하게 써주세요" 같은 막연한 지시 대신, 검색 가능한 금지 패턴 목록과 자가 점검 워크플로우를 사용합니다.

인터랙티브 데모 1 · 컨텍스트 드리프트 시뮬레이터

아래는 시뮬레이션된 대화 창입니다. 컨텍스트 윈도우가 최근 20턴만 담을 수 있다고 가정합니다. 1턴에서 "PostgreSQL 사용" 이라는 하드 제약을 설정했습니다. 슬라이더를 드래그하여 턴 수를 늘리고 이 합의가 어떻게 되는지 지켜보세요. 그런 다음 "앵커링 켜기"로 전환하여 동일한 30턴 후 무슨 차이가 있는지 확인하세요.

1턴 · 합의가 방금 설정됨
1턴

회색 취소선이 있는 메시지는 컨텍스트 윈도우 밖으로 나간 것입니다 — AI는 더 이상 볼 수 없습니다. 이 데모는 윈도우 용량이 최근 20턴이라고 가정합니다.

앵커링 규칙의 세 가지 핵심

고정된 형식으로 복술

코드 수정, 설정 변경, 배포 전에 AI는 현재 목표와 핵심 제약 조건을 고정 형식으로 검토하고 복술해야 합니다 — 한눈에 확인하기 쉽습니다.

📌 현재 목표: XXX | 핵심 제약: YYY

최신 목표가 우선

대화 중 사용자가 목표를 수정했을 때, 복술은 최신 버전을 기준으로 해야 하며 변경 사항을 명확히 표시해야 합니다 — 구 목표와 신 목표가 뒤섞이지 않도록.

병렬 편집 전 파일 재읽기

여러 SubAgent 또는 여러 번의 편집이 같은 파일에 관여할 때, 이후 수정은 반드시 파일의 현재 상태를 먼저 다시 읽어야 합니다. 캐시나 기억 속의 오래된 내용을 기반으로 편집하는 것은 금지됩니다. 이것은 멀티 Agent 시대의 "낙관적 잠금"입니다.

인터랙티브 데모 2 · AI 어조 감지기

아래 텍스트는 AI가 중국어로 생성한 것으로, 전형적인 "AI 어조" 패턴이 가득합니다. (참고: 이 데모는 중국어 작문 규범을 대상으로 합니다 — 감지 규칙이 적용되도록 샘플 텍스트는 의도적으로 중국어로 유지됩니다.) "감지 시작"을 클릭하여 writing-style.mdc 체크리스트에 따라 각 금지 패턴을 스캔하세요. 빨간색 하이라이트를 클릭하면 어떤 규칙을 위반했는지, 어떻게 수정해야 하는지 볼 수 있습니다.

감지할 텍스트 (교육 샘플 — 중국어, 의도적으로 "매우 AI답게" 작성)
수정 전 · 7가지 금지 패턴 유형 감지됨
수정 후 · ✅ 작문 규범 자가 점검 완료
这次升级是一场彻底的重构，我们把整个数据层推倒重来。新架构跑通之后，接口平均响应从 900 毫秒降到了 200 毫秒。同事看完方案补了一条索引建议。这个设计的判断是：性能不该靠堆机器解决。
두 가지 설계 세부사항

첫 번째: "자연스럽고 유창하게 써주세요"는 효과가 없습니다. AI가 생각하는 자연스러움과 당신이 생각하는 자연스러움이 완전히 다를 수 있습니다. 구체적인 금지 단어와 금지 문장 패턴 목록을 제공해야만 AI가 정확하게 실행할 수 있습니다. 납품 전에 금지 패턴을 하나씩 검색하고, 발견하면 수정하고, 완료 후 자가 점검 완료를 기록하세요. System Prompt의 금지 문장도 똑같이 수정해야 합니다.

두 번째: 작문 규범을 별도 파일로 만들고 alwaysApply: false로 설정하세요 — 글이나 Prompt를 작성할 때만 수동으로 참조하여 코딩 대화 컨텍스트를 오염시키지 않도록 합니다.

핵심 정리

앵커는 망각에 대항하고, 체크리스트는 모호함에 대항합니다. 긴 대화에서는 주기적인 복술로 합의를 지키고, 작문에서는 검색 가능한 금지 패턴으로 스타일을 지킵니다. 두 가지의 공통점은 모호한 기대를 실행 가능한 행동으로 바꾼다는 것입니다.
