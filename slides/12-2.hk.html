CHAPTER 12 · ENGINEERING CHOICE

為什麼 Rust 合適：先分清事實與推斷

源碼能證明 Rust 2024、Tokio、強類型建模和原生二進制產物。技術選擇背後的組織動機沒有寫入源碼，本課只給出有邊界的課程推斷。

一句話速覽

從源碼可驗證事實出發，分析類型系統、併發安全和分發方式帶來的工程取捨

課程目標
用「倉庫證據」和「工程推斷」兩套標籤分析技術選型，避免把合理解釋寫成 xAI 官方動機。
源碼可驗證事實

Rust 2024

[workspace.package] 明確設定 edition = "2024"。

Tokio 全功能

workspace 依賴使用 Tokio 1，並啓用 full feature。

強類型狀態

enum、Result、newtype 與 Actor handle 廣泛用於邊界建模。

二進制目標

xai-grok-pager-bin 定義一個名為 xai-grok-pager 的 bin target。

證據邊界
源碼事實

倉庫直接支持的結論

  • 入口創建 Tokio 多綫程 runtime。
  • 會話另建 current-thread runtime 與 LocalSet。
  • release-dist 配置 panic、LTO、codegen units 等原生發佈參數。
  • 類型系統承載 Agent、Session、Sampler、Prompt 等領域邊界。
課程推斷

可討論的工程收益

  • 原生二進制便於把 CLI 與運行時一起交付。
  • 所有權與 Send 邊界有助於管理多綫程會話。
  • 強類型適合複雜協議、工具參數和狀態轉換。
  • 代價包括編譯時間、生命週期約束與更高學習門檻。

這些是基於程式碼形態的解釋，不代表 xAI 官方披露的選型原因。

公開行為對照

Grok Build 與 Claude Code

Grok Build 本地源碼
可驗證 Rust workspace、原生 bin target、Tokio runtime 和 crate 邊界。
Claude Code 公開行為
公開安裝文檔提供原生安裝方式，也提供 Homebrew、WinGet 等方式。用戶可見行為包括終端交互、無頭模式和工具調用。
此處僅比較公開可驗證的安裝與產品行為，不推斷 Claude Code 的私有內部實現、語言或併發架構。
源碼快照説明：本頁依據本地同步副本核對。該副本沒有 .git 元數據，因此不聲稱對應某個 commit 版本。
課堂練習

給每條結論貼標籤

判斷下列陳述屬於「源碼事實」還是「課程推斷」：使用 Rust 2024、入口採用 Tokio、多綫程一定更快、xAI 為降低記憶體佔用選擇 Rust。最後兩條缺少倉庫直接證據。

Takeaway：技術選型分析先建立證據邊界。Rust 2024、Tokio、類型邊界和 bin target 屬於事實，性能收益與團隊動機需要標為推斷並接受驗證。
