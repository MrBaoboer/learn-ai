MCP 실전

MCP는 단순한 「도구 호출」 이상입니다

대부분의 사람들은 MCP를 단순히 「AI가 외부 도구를 호출하는 것」으로 이해합니다. 하지만 MCP 프로토콜은 양방향입니다: Alice가 다른 도구를 호출할 수 있을 뿐만 아니라, Cursor 같은 외부 클라이언트가 Alice의 기능을 호출할 수도 있습니다.

두 가지 역할, 하나의 프로토콜

Client로서 (소비자)

Alice는 외부 MCP 서비스에 연결해 다른 곳이 제공하는 도구 기능을 호출합니다:

  • 캘린더 MCP — 일정 조회 및 생성
  • 이메일 MCP — 이메일 읽기 및 쓰기
  • 데이터베이스 MCP — 데이터 쿼리
  • 브라우저 MCP — 웹페이지 접근

핵심: Alice가 능동적으로 요청을 시작해 외부 기능을 획득합니다.

Server로서 (제공자)

Alice는 자신의 기능을 MCP 프로토콜을 통해 외부에 노출시켜 호출될 수 있게 합니다:

  • Cursor — 코딩 중 Alice를 호출해 노트 검색
  • Claude Desktop — Claude가 Alice에게 메시지 전송 가능
  • 자동화 스크립트 — 정기적으로 Alice를 트리거해 작업 실행

핵심: Alice는 수동적으로 요청을 받아 자신의 기능을 제공합니다.

왜 양방향이 중요한가요?
단방향 통합은 단순한 도구 호출로, API와 본질적으로 다르지 않습니다. 양방향 통합은 AI가 도구를 사용할 뿐만 아니라 도구가 될 수도 있음을 의미합니다. 여러 AI Agent가 서로를 호출할 수 있게 되면 AI 생태계가 자연스럽게 형성됩니다.
MCP는 단순히 AI가 도구를 호출하는 것이 아닙니다 — AI가 다른 AI 시스템에 의해 호출될 수 있게 합니다. 이것이 생태계의 힘입니다. 하나의 프로토콜, 양방향 통합: 도구에서 플랫폼으로의 핵심 도약.
