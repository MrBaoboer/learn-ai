프로그래밍 기초 · 트리와 그래프: AI의 홈그라운드

그래프: 지식 그래프에서 멀티 Agent 협업까지

지난 강의의 트리는 규칙이 빡빡했어요: 부모는 하나, 사이클은 금지. 현실 관계는 훨씬 지저분하죠—친구끼리도 친구고, 회사·학교·사람이 한데 얽혀요. 「부모는 하나」 규칙을 찢으면 트리가 그래프: 노드 + 관계, 마음대로 연결로 업그레이드됩니다. 이번 강의는 AI 세계에서 그래프의 두 홈그라운드를 봅니다.

한 줄 요약

노드에 관계를 더하면 그래프예요: 소셜 네트워크, 지식 그래프, Agent 워크플로 DAG. 노드 하나를 눌러 관계가 한 겹씩 퍼지는 걸 보세요

홈그라운드 1 · 지식 그래프: 한 번 누르면 지식이 퍼져요

아래는 미니 지식 그래프예요: 점은 엔티티(사람·회사·학교·제품), 선은 관계예요. 아무 노드나 클릭하면 관계가 한 바퀴씩 퍼져요—「홉 수」를 눈여겨보세요: 한 홉은 직접 아는 사이, 두 홉은 「친구의 친구」예요.

인물 회사 학교 제품 👆 노드를 눌러 보세요
아직 노드를 안 눌렀어요. 「레이쥔」을 눌러 보세요—두 홉 안에 어떤 지식이 퍼지는지.
AI가 복잡한 질문에 답하는 비결이 바로 이 「멀티 홉」이에요. 「레이쥔 모교의 유명 동문은 또 누구?」—어느 자료에도 답이 직접 없지만, 그래프를 두 홉 가면(레이쥔 → 우한대학교 → 천둥성) 맞춰집니다. 지식 그래프는 흩어진 사실을 그물로 잇고, RAG가 노드에 닿은 뒤에도 줄기를 따라갈 수 있어요—그게 그래프 검색 증강(GraphRAG)이고, 텍스트만 검색할 때보다 꼬인 질문에 더 잘 답해요.
홈그라운드 2 · 멀티 Agent 워크플로: 왜 DAG여야 하나요

이제 Agent 팀이 조사 보고서를 함께 씁니다. 각 상자는 작업, 화살표는 「앞이 끝나야 시작」이에요. 「실행」을 누르고 두 가지를 보세요: 서로 의존이 없으면 동시에 켜집니다(병렬); 각 작업은 화살표 출발점이 전부 초록이 돼야 움직여요. 그다음 「사이클 만들기」를 누르고 한 번 더 실행해 보세요.

Agent 7명이 대기 중. 노랑 = 작업 중, 초록 = 완료.
「방향 비순환 그래프」(DAG)는 전문 용어가 아니라 상식이에요: 의존 화살표엔 방향(선후)이 있고, 원이 되면 안 돼요—사이클이 생기면 「너 나 기다려, 나 그 기다려, 그 너 기다려」 삼각 부채가 되어 아무도 시작 못 해요. 모든 멀티 Agent 오케스트레이터는 제출 시 「사이클 검사」를 하고, 발견하면 실행을 거절합니다—방금 본 데드락을 막으려는 거죠.

🌳

트리는 그래프의 「착한 아이」

트리도 그래프예요. 다만 규칙이 둘 더 있어요: 부모는 하나, 사이클 금지. 그래서 지난 강의의 파일 트리·AST도 그래프 알고리즘으로 다룰 수 있어요—그래프가 더 큰 우산입니다.

🕸

그래프 = 노드 + 관계

공식은 이 하나예요. 소셜 네트워크(사람 + 팔로우), 지도 안내(교차로 + 도로), 지식 그래프(엔티티 + 사실), Agent 워크플로(작업 + 의존)—「누가 누구와 관계인지」만 말할 수 있으면 그래프로 그릴 수 있어요.

이 강의가 전하고 싶은 것

  • 관계가 곧 그래프: 노드 + 관계가 그래프; 트리는 「부모 하나·사이클 없음」인 특수 그래프일 뿐
  • 멀티 홉으로 답을 찾다: 지식 그래프를 관계 따라 두세 홉 가면, 자료에 없는 질문에도 답할 수 있어요
  • 사이클이 없어야 시작: 워크플로에 사이클이 있으면 서로 기다리다 전원이 멈춥니다—그래서 DAG여야 해요
  • 병렬은 그래프 안에: 의존이 없는 작업은 동시에—멀티 Agent 가속의 원천이에요
  • 검수할 때 한 마디: AI가 짠 워크플로에 「사이클 검사했나요? 어떤 단계가 병렬인가요?」
