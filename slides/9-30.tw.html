MCP 實戰

MCP 不只是「調工具」

大多數人理解 MCP 就是「讓 AI 調外部工具」。但 MCP 協議是雙向的：Alice 不僅能調別人的工具，也能讓 Cursor 等外部客戶端來呼叫 Alice 的能力。

兩個角色，一個協議

作為 Client（消費者）

Alice 連線外部 MCP 服務，呼叫別人提供的工具能力：

  • 日曆 MCP — 查看和建立日程
  • 郵件 MCP — 讀寫郵件
  • 資料庫 MCP — 查詢資料
  • 瀏覽器 MCP — 訪問網頁

關鍵：Alice 主動發起請求，取得外部能力。

作為 Server（提供者）

Alice 把自己的能力透過 MCP 協議暴露出去，被外部呼叫：

  • Cursor — 在程式設計時呼叫 Alice 搜尋筆記
  • Claude Desktop — 讓 Claude 發訊息給 Alice
  • 自動化腳本 — 定時觸發 Alice 執行任務

關鍵：Alice 被動接收請求，提供自身能力。

為什麼雙向很重要？
單向整合只是工具呼叫，跟 API 沒有本質區別。雙向整合意味著 AI 不僅能用工具，還能成為工具。當多個 AI Agent 都能互相呼叫時，一個 AI 生態就自然形成了。
MCP 不只是讓 AI 調工具，它讓 AI 也能被別的 AI 呼叫，這才是生態的力量。同一個協議、雙向整合，是從工具到平臺的關鍵跨越。
