어떤 문제를 푸는가

누가 Claude Code에서 자동으로 이사한다고 했습니다. 설정 디렉터리 전체를 복사하는 줄 알았죠. 다음날 hook이 하나 없고, MCP가 한 대 없고, memory는 목록에 없어요. 빠진 hook은 type: prompt였고, 빠진 MCP 명령에는 ${API_KEY}가 있었습니다.

동료를 한 명 더 바꿔 볼게요. Cursor를 씁니다. Codex는 그의 skill과 hook은 보고, memory는 못 봅니다. 저장소 안 Cursor 플러그인 설정은 바로 버려져요.

어떤 문제를 푸는가

Claude Code는 저장소 settings에 사용 플러그인 목록을 실을 수 있어, 동료가 clone하면 같은 플러그인이 자동으로 생깁니다. Codex에게 저장소 사용 목록은 설치 권위가 아니에요. 설치하면 사용자 설정에 들어갑니다. 믿을 수 없는 저장소가 당신 머신에 실행 파일을 올리려는 길은 먼저 끊어야 합니다.

아이디어는 무엇인가

탐지는 home에서만 플러그인을 훑습니다. 주석이 박혀 있어요. 저장소가 통제하는 settings는 설치 권위가 될 수 없다. Cursor는 저장소 루트만 보면 플러그인 탐지가 빈 값을 바로 돌립니다. 가져오기가 비어 있지 않은 작업 디렉터리를 보면 repository-scoped plugin migration is not allowed를 냅니다.

실행 파일의 설치 권위는 사용자 급에 있어야 합니다. 아무 git clone이나 받는 제품에는 home-only가 더 안전해요. 동기는 먼저 영수증을 주고 느린 일은 백그라운드로 보내는 것이, 긴 작업 API의 흔한 모양입니다.

어떤 필드가 목록에 들어가나

책상 위에 Claude Code 자산이 넷 있어요. PreToolUse의 type: command hook, 같은 이벤트의 type: prompt hook, command에 ${API_KEY}가 있는 MCP 한 대, 40일 전 세션 하나. 위의 허용 목록을 보고, 탐지 목록에 나와야 할 것과 나오면 안 되는 항목을 적으세요.

한 가지 더: 호출 쪽이 언제 import_id를 받고, 이 세션이 언제 thread가 되는지. 스위치가 꺼진 memory를 가져오기로 보내면 어느 문에서 막히는지.

Takeaway:이사는 탐지 더하기 매핑 더하기 개서입니다. 맞는 필드는 복사하거나 고치고, 안 맞는 것은 버립니다. 플러그인은 사용자 급에서만 설치하고, 세션과 원격 마켓은 백그라운드로 갑니다. 목표가 비어 있지 않으면 덮지 않아요.
