安全分類框架

每種 AI 產品面對的威脅模型不同，但所有風險都可以歸入三個類別。理解這三類風險是設計安全架構的第一步。

MISUSE
用戶濫用
用戶故意讓 Agent 做不該做的事情。這是來自用戶側的主動威脅。
  • 利用 Agent 生成釣魚郵件
  • 誘導 Agent 執行惡意程式碼
  • 利用 Agent 取得未授權的數據
  • 通過越獄攻擊繞過安全限制
MISBEHAVIOR
模型失控
模型自發的錯誤行為：沒人指使它，但它自己做了不該做的事。
  • 過度行動：用戶只讓查看文件，模型卻自作主張修改了
  • 幻覺驅動操作：基於虛構信息執行了真實操作
  • 權限越界：模型嘗試存取不屬於當前任務的資源
  • 停不下來：Agent 進入無限循環
EXTERNAL ATTACK
外部攻擊
第三方通過注入惡意內容來操控 Agent 的行為。攻擊來自數據源，用戶本身可能毫不知情。
  • Prompt Injection：網頁/文檔中嵌入攻擊指令
  • 供應鏈攻擊：惡意 MCP 伺服器返回篡改數據
  • 數據投毒：訓練數據中植入後門
  • 間接注入：通過 Agent 讀取的郵件/文件注入指令
雙層 Containment 策略

MODEL LAYER 模型層防綫

通過訓練讓模型從內心傾向於安全行為，就像培養一個有良好價值觀的員工。
  • RLHF/Constitutional AI 訓練安全偏好
  • 模型學會拒絕危險請求
  • 模型在不確定時主動詢問用戶
  • 遵循最小權限原則

ENVIRONMENT LAYER 環境層防綫

通過系統架構讓危險操作無法執行，就像給倉庫加鎖，不依賴員工的自覺。
  • 沙箱隔離：程式碼執行在受限環境中
  • 權限控制：按任務粒度授權
  • 審批機制：高危操作需人工確認
  • 網絡隔離：限制 Agent 的網絡存取範圍
兩者互補，缺一不可。模型層是讓 Agent 想做對的事，環境層是讓 Agent 即使想做錯也做不到。只靠 Prompt 告訴模型「別做壞事」是不夠的，你還需要在架構上讓壞事不可能發生。
MCP 的雙重風險

Model Context Protocol 帶來的新攻擊面

SUPPLY CHAIN RISK
供應鏈風險
不可信的 MCP 伺服器可能注入惡意內容。Agent 信任 MCP 返回的工具描述和數據，但這些數據可能已被篡改。一個惡意的 MCP 伺服器可以通過修改工具描述來操控 Agent 的行為：Agent 以為自己在用「搜索文件」工具，實際上在執行刪除操作。
PROMPT INJECTION
注入攻擊
MCP 返回的內容可能包含攻擊指令。即使 MCP 伺服器本身沒有惡意，它返回的數據（比如從網頁抓取的內容）可能包含 Prompt Injection 攻擊。Agent 處理這些數據時，可能被説服執行非預期的操作。
MCP 本質上擴大了 Agent 的攻擊面。每多接入一個 MCP 伺服器，就多了一個潛在的數據注入入口。產品設計者需要像審核第三方 SDK 一樣審核每個 MCP 集成，信任但要驗證。

分類器負責快速判斷每個操作的風險等級：安全操作直接執行，可疑操作才彈窗詢問。沙箱作為第二道防綫，確保即使分類器誤判，程式碼執行也不會對系統造成真實損害。兩者組合，讓用戶減少了約 83% 的確認彈窗，同時保持了安全性。
安全不是加一層提示詞就夠的，需要結構性設計。理解三類風險（濫用、失控、攻擊），在模型層和環境層同時構建防綫，才能讓 Agent 在實際生產環境中安全運行。
