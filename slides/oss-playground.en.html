08b-3 · Why this example
Class .oss-why. When the chapter keeps using the same brand as the running example, put the reason on the table. Style stays light — pale background, no shadow, never louder than the body copy. It is a disclosure, not a pitch. Three hard rules for the copy: reasons must be checkable facts, not adjectives; include at least one fact that is unflattering to the brand; end by saying “using it as an example does not mean it is the best.” Appears once, at the chapter opening.

Most examples in this chapter come from one family — here is why, up front.

  • The size lineup is the most complete. The official library runs from the smallest tier to the largest with no gaps, so every device tier maps to a file you can actually download.
  • Others pick it as a base. Most third-party derivatives choose it — that is other people’s choice, not self-promotion.
  • It is also a cautionary tale. Early builds used a non-standard license — perfect for showing how unreliable the word “open source” can be.

The community has nicknames for it, but those are fan labels, not a ranking. We use it because the materials are complete and easy to hands-on with — not because it is the best.

08b-4 · Quantization ruler & ranking flip
Classes .qz-ruler / .qz-vals / .qz-cands, used in oss-8. The problem they solve: readers remember “fewer bits means loss” but cannot act on it — they do not know which tier to pick. The ruler is the core: INT4’s 16 ticks are countable by eye; INT8 is so dense it can only be drawn as a band, so the gap between tiers is visible without explanation. Above 64 levels, switch to .is-dense background bands — drawing every tick would just be a black smear, slow and dishonest. Red dots mark weights flattened to 0; several weights landing on the same spot is intentional, not a bug — that is “different values squeezed into one bin” itself. In the candidate list, .is-top must outrank .is-moved, or after a perturbation all four rows turn orange and you cannot see who actually moved up. Every number comes from the quantization helpers in oss-calc.js — do not hard-code pretty figures on the page; readers can verify these themselves.

08c · Feedback motion (click to preview)
Always go through OSSInteract.fire(el), which adds a one-shot .fire class. The class is not removed when the animation ends, so before retriggering you must remove it and force a reflow — that step is already inside fire; do not add the class yourself. When you need “flash only if the state actually changed,” use fireOnChange(el, key, store, slot): it compares against the last key and skips when identical, so the whole block does not shake on every slider tick. Under reduced-motion, both JS and CSS intercept — missing either side makes those users wait out a full animation duration for nothing.
