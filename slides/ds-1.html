都 2026 年了，为什么还要懂数据结构？

AI 都会写代码了，还要学这个「程序员基本功」吗？先说结论：你可以不写代码，但要会验收 AI 写的代码。这一章不背定义、不手写链表，只给你一副能看穿代码的眼镜。第一课先玩个游戏。

同样的东西，收纳方式不同，找起来差了一个量级。这就是数据结构的全部秘密：数据结构 = 数据的收纳方式。大抽屉就是「数组里挨个找」，收纳盒就是「先分类再直达」。东西越多，差距越悬殊——36 件是翻 20 次和 3 次的区别，36 万件就是「等一下」和「瞬间」的区别。记住这个隐喻，全章 8 种结构都是不同的收纳方式。
这和 AI 有什么关系？

你可能会说：收纳是程序员的事，AI 替我写代码，它收纳去。问题是——AI 两种都可能写。同一句需求「查用户是否在会员名单里」，AI 给出的两个版本都能跑通、界面上看不出任何差别。拖动名单人数，看看差别藏在哪。

1,000 人
AI 的版本 A 大抽屉
for (const m of members) { if (m === user) return true; } // 从头翻到尾
每次查询约0.01 毫秒
AI 的版本 B 收纳盒
const set = new Set(members); return set.has(user); // 直达，不用翻
每次查询约0.0001 毫秒
这就是「验收」的含义。Demo 阶段名单只有 100 人，两个版本都是「瞬间」；上线半年名单涨到 100 万，版本 A 的页面开始卡成幻灯片——而写下它的 AI 早就不在对话里了。懂收纳方式的人，在合并代码那天就会问一句：「这里为什么用数组挨个找？」这一问，价值就出来了。
