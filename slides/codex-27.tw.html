思路一 · 三條出口：原樣、改寫、丟掉
它解決什麼問題

有人告訴你會自動從 Claude Code 搬家。你以為是把整個配置目錄拷過來。第二天 hook 少了一條，MCP 少了一臺，memory 沒出現在清單裡。少掉的 hook 用了 type: prompt。少掉的 MCP 命令裡寫了 ${API_KEY}。

再換一個同事。他用的是 Cursor。Codex 能看見他的 skill 和 hook，看不見他的 memory。倉庫裡的 Cursor 外掛配置會被直接丟掉。

思路是什麼

搬家 crate 只負責把外部配置讀進來。外掛怎麼跑，在旁邊的 core-plugins。源在型別上只有兩個變體：Cla 是 Claude Code，Cur 是 Cursor。字串對不上 cursor，就落到 Claude Code。呼叫方漏傳源，檢測會去翻 ~/.claude。

出處：codex-rs/external-agent-migration/src/migration_source.rs 第 51 至 67 行

一次檢測最多產出十種條目。每種後面的匯入必須給一個去處。欄位先過白名單。Codex 認 11 個 hook 事件，Claude Code 發出 27 個。名字對不上的組，整組消失。單條 hook 的 type 預設當 command，對不上就跳過。MCP 的 command 或 url 裡出現 ${，整臺不要。市場來源只收 github、git、本地目錄。file、url、npm、settings 直接丟掉。

然後說明檔案要改名。CLAUDE.md 變成 AGENTS.md。產品名按詞邊界改成 Codex。Cursor 只用大小寫敏感的 Cursor，避免把普通英文 cursor 一起改掉。

出處：codex-rs/external-agent-migration/src/rewrite.rs 第 38 至 49 行

教學化結構圖：搬家不是整目錄複製，每條欄位單獨走出口。
為什麼長期成立

匯入器的通用形狀是白名單加三條出口。對不上的欄位丟掉，不要改寫成近似物。prompt hook 不會被塞進 command。帶佔位符的 MCP 不會被瞎展開。換個語言重寫，這份表還用得上。

思路二 · 外掛只從使用者級裝，慢活進後臺
它解決什麼問題

Claude Code 允許倉庫 settings 帶著啟用外掛名單，同事克隆之後自動有同一批外掛。對 Codex 來說，倉庫裡的啟用名單不能當安裝權威。裝上去會進使用者配置。不可信倉庫想在你機器上裝可執行內容，這條路要先切斷。

思路是什麼

檢測只在 home 掃外掛。註釋寫死了：倉庫控制的 settings 不能當安裝權威。Cursor 只要看見倉庫根，外掛檢測直接返回空。匯入看見非空工作目錄，報 repository-scoped plugin migration is not allowed。

出處：codex-rs/external-agent-migration/src/detect/mod.rs 第 330 至 332 行 · codex-rs/external-agent-migration/src/migration_source.rs 第 116 至 125 行 · codex-rs/external-agent-migration/src/plugins.rs 第 26 至 36 行

本地外掛當場裝。遠端市場推進待裝佇列。會話也是兩截：檢測清單裡可以有，同步 import() 對 Sessions 直接返回成功，什麼都不寫。真正寫成 Codex thread 的，是 app-server 裡的後臺任務。呼叫方先拿到 import_id。

出處：codex-rs/external-agent-migration/src/service.rs 第 437 行 · codex-rs/app-server/src/external_agent_migration/session_importer.rs 第 100 至 111 行

Codex 認市場清單時，按固定相對路徑找第一個存在的檔案。四條路徑裡兩條是自己的，兩條是競品的。同一套查詢同時服務「使用者主動加市場」和「從競品搬市場」。

出處：codex-rs/core-plugins/src/marketplace.rs 第 20 至 25 行

教學化時序圖：同步階段承認「看見了」，慢活留給後臺。
為什麼長期成立

可執行內容的安裝權威必須落在使用者級。面向任意 git clone 的產品，home-only 更穩。同步先回執、慢活進後臺，是長任務介面的通用形狀。

思路三 · 目標非空不覆蓋
它解決什麼問題

換產品最怕把已經改過的新配置蓋掉。目標 hooks.json 裡已經有內容，整檔案替換會把使用者手寫的 hook 沖掉。

思路是什麼

目標 hook 檔案非空，整項取消。已有 config.toml 只補缺失鍵。MCP 同名 server 保留舊的。第一次搬家像填空。第二次再點遷移，多數條目會因為已經有了而不出現。

出處：codex-rs/external-agent-migration/src/hooks_common.rs 第 13 至 19 行

memory 另有一道門。特性開關預設關，階段是 UnderDevelopment。檢測函式不看這個開關，匯入前處理器會查。關著就回 external agent memory import is disabled。匯入按位元組複製，不脫敏。

出處：codex-rs/features/src/lib.rs 第 998 至 1003 行 · codex-rs/app-server/src/external_agent_migration/processor.rs 第 180 至 185 行

對得上的欄位走拷或改，對不上的丟掉。
為什麼長期成立

匯入是填空。使用者已經寫過的檔案，搬家碰不得。memory 預設關，是因為另一家 agent 的專案記憶會按明文進盤。

DeepSeek Harness：不搬家，再裝一次

DSH 的外掛入口是 thin pnpm forwarder。初始化 profile，在 profile 目錄裡跑 pnpm，再按安裝結果調和清單。外掛是 npm 包。沒有檢測 Claude Code，沒有匯入 Cursor hook。換產品要自己重灌。代價是使用者稅。好處是不用對一家不斷加欄位的 settings schema 做永久相容。
