教科書的 3 步 vs 真實的 N 步

教科書說 Agent 迴圈是「想→做→看」三步。但當你真正把 Agent 推上生產環境，每轉一圈要做的事比你想像的多得多。

一句話速覽

ReAct 不止 Think-Act-Observe 三步，生產環境每輪還要做什麼

2 Act — 呼叫一個工具
3 Observe — 拿到結果，決定下一步

為什麼多出來這麼多？
教科書省略的部分，恰恰是讓 Agent 穩定、安全、可用的關鍵：
  • 上下文壓縮 — 對話越來越長，不裁剪就會超出視窗
  • 權限校驗 — 這個工具使用者有沒有權限調？參數合不合法？
  • 併發排程 — 多個工具能同時跑嗎？怎麼協調？
  • 錯誤處理 — 工具超時了怎麼辦？返回格式錯了怎麼辦？
  • 結果回寫 — 執行結果要寫回上下文、更新狀態、觸發通知
  • 安全審計 — 記錄每一步操作，以防出問題可追溯
真實的 Agent 每轉一圈，要做的事比你想的多 5 倍。教科書的 3 步只是骨架，生產環境的每一輪迴圈裡藏著權限、壓縮、容錯、審計等大量隱藏邏輯，這些才是 Agent 工程的核心工作量。
