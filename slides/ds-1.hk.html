都 2026 年了，為什麼還要懂數據結構？

AI 都會寫程式碼喇，仲要學呢個「程序員基本功」？先説結論：你可以不寫程式碼，但要會驗收 AI 寫的程式碼。這一章不背定義、不手寫鏈表，只給你一副能看穿程式碼的眼鏡。第一課先玩個遊戲。

同樣的東西，收納方式不同，找起來差了一個量級。這就是數據結構的全部秘密：數據結構 = 數據的收納方式。大抽屜就是「陣列裏挨個找」，收納盒就是「先分類再直達」。東西越多，差距越懸殊——36 件是翻 20 次和 3 次的區別，36 萬件就是「等一下」和「瞬間」的區別。記住這個隱喻，全章 8 種結構都是不同的收納方式。
呢樣同 AI 有咩關係？

你可能會説：收納是程序員的事，AI 替我寫程式碼，它收納去。問題是——AI 兩種都可能寫。同一句需求「查用戶是否在會員名單裏」，AI 給出的兩個版本都能跑通、介面上看不出任何差別。拖動名單人數，看看差別藏在哪。

for (const m of members) { if (m === user) return true; } // 從頭翻到尾

AI 的版本 B 收納盒
const set = new Set(members); return set.has(user); // 直達，不用翻
每次查詢約0.0001 毫秒
這就是「驗收」的含義。Demo 階段名單只有 100 人，兩個版本都是「瞬間」；上綫半年名單漲到 100 萬，版本 A 的頁面開始卡成幻燈片——而寫下它的 AI 早就不在對話裏了。懂收納方式的人，在合併程式碼那天就會問一句：「呢度點解用陣列逐個搵？」這一問，價值就出來了。
