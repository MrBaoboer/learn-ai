심화 마무리

심화 전체 개요

Workflow에서 Agent까지, Prompt Engineering에서 Context Engineering까지 - 이 챕터는 핵심 엔지니어링 실습을 다룹니다. 모든 주제를 연결하여 완전한 지식 지도를 형성해 봅시다.

CHAPTER REVIEW

7가지 주제, 하나의 완전한 Agent 지식 체계

각 주제는 실제 프로덕션에서 검증된 엔지니어링 경험입니다. 이들은 설계부터 배포까지 완전한 방법론을 함께 구성하며 고립된 지식 포인트가 하나도 없습니다.
설계 패턴
5가지 Workflow 패턴(Prompt Chaining, Routing, Parallelization, Orchestrator-Workers, Evaluator-Optimizer) + 자율 Agent. 핵심 원칙: 단순함에서 복잡함으로, 가장 단순한 방안부터 시작하여 점차 업그레이드합니다.
먼저 Workflow, 그 다음 Agent
컨텍스트 엔지니어링
Prompt Engineering에서 Context Engineering으로의 진화입니다. 컨텍스트 창은 희소 자원이며 모든 Token에는 비용이 있습니다. 주의력 예산은 유한하여 정보의 선별과 조직이 정보량보다 중요합니다.
주의력은 희소 자원
도구 설계
ACI(Agent-Computer Interface)는 Agent와 세계의 계약입니다. 4가지 원칙: 생각할 공간 제공, 학습 데이터에 근접, 형식 오버헤드 감소, Poka-yoke 실수 방지. Agent 자체를 사용하여 도구 설계를 최적화합니다.
도구 설계 = Agent의 UI
평가
3가지 Grader 모드(코드, LLM, 인간)와 3가지 핵심 함정(노이즈, 속임수, 퇴화). 평가 없이는 최적화도 없습니다. 하지만 평가 자체도 평가되어야 합니다.
No eval, no improvement
장기 실행 Agent
이중 역할 Harness 아키텍처: 두뇌와 손의 분리. Session ≠ Context: 컨텍스트는 창을 초과하거나 만료되거나 표류할 수 있습니다. 구조화된 로그와 체크포인트가 장기 실행 신뢰성의 핵심입니다.
Session ≠ Context
보안
3가지 위험 유형(남용, 통제 불능, 외부 공격), 2층 방어선(모델 계층 + 환경 계층). 구조적 자격 증명 격리: 생성된 코드와 키는 절대 같은 곳에 있어서는 안 됩니다.
구조적 보안 > Prompt 보안
검색 증강
Contextual Retrieval은 전통적인 RAG의 핵심 문제를 해결합니다: Chunk가 컨텍스트에서 분리될 때 정보 손실. 각 Chunk에 컨텍스트 접두사를 추가하면 검색 실패율이 67% 감소합니다.
Chunk는 컨텍스트를 포함해야 함
CORE PRINCIPLES

3가지 핵심 원칙

1
작동하는 가장
단순한 것부터 하세요
가장 단순한 방안부터 시작합니다. 대부분의 문제는 Agent가 필요하지 않으며 Workflow도 필요 없을 수 있습니다. 먼저 좋은 Prompt로 시도해보고 부족하면 복잡도를 추가하세요. 모든 복잡도 레이어는 비용입니다.
2
컨텍스트는 희소 자원
모든 Token에는 비용이 있습니다
컨텍스트 창은 유한한 주의력 예산입니다. 무한한 쓰레기통처럼 사용하면 역효과가 납니다. 관련 없는 정보를 넣으면 돈을 낭비할 뿐 아니라 모델의 주의력을 분산시켜 출력 품질을 저하시킵니다. 적을수록 더 좋습니다.
3
구조적 보안이
Prompt 보안보다 중요합니다
"Prompt에 나쁜 일 하지 말라고 모델에게 말하기"에 의존하지 마세요. 아키텍처 설계(샌드박스, 자격 증명 격리, 권한 계층화)를 통해 위험한 작업이 구조적으로 불가능하도록 만드세요.
