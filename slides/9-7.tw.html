Agent 實戰

為什麼 Agent 會卡死

實驗室裡的 Agent 死迴圈很好發現：控制台一刷就看到了。但生產環境的卡死更隱蔽：使用者不會說「你的 Agent 死迴圈了」，他只會說「你的 AI 怎麼那麼慢」或者「它是不是呆掉了」。

真實場景中迴圈掛掉的幾種典型模式，以及使用者會看到什麼

四種生產環境特有的卡死模式
同參數死迴圈
Agent 連續 3 次用完全相同的參數呼叫同一個工具

模型忘了上次已經做過這件事，或者認為上次沒成功所以要重試，但參數一模一樣，結果也一模一樣。

使用者看到的表現
「它轉了好久都沒動靜」「怎麼一直在載入」

典型場景：反覆讀取同一個檔案、反覆搜尋同一個關鍵詞、反覆呼叫同一個 API

收益遞減
跑了 50 輪迴圈，但幾乎沒產出有價值的內容
點選查看詳情

Agent 在忙，但每一輪只做邊緣操作：整理格式、反覆確認、做無關搜尋。看起來在工作，實際沒有推進核心目標。

使用者看到的表現
「等了兩分鐘，結果就給我這個？」「AI 是不是在空轉」

典型場景：Agent 在複雜任務中迷失方向，不斷做安全但無用的小動作

文字復讀
模型開始重複自己說過的話，一段內容反覆出現
點選查看詳情

當上下文過長或模型困惑時，它會退化為復讀模式：把之前的輸出再生成一遍。模型並沒有卡住，它已經迷路了。

使用者看到的表現
「它翻來覆去講同一段」「怎麼又是這一段」

典型場景：長對話後期、上下文接近視窗上限、任務描述模糊

工具連續失敗雪崩
一個工具掛了，Agent 瘋狂重試，拖垮整條鏈路
點選查看詳情

工具 A 超時 → Agent 重試 → 還是超時 → 換個方式調 → 還是不行 → 試工具 B 來繞過 → B 依賴 A 的結果也掛了 → 雪崩。

使用者看到的表現
「它好像卡住了」「等好久突然跳出失敗」

典型場景：外部 API 限流、資料庫連線池耗盡、第三方服務臨時當機
