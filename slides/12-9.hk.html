源碼中的實現族
grok_build

主要產品工具族，包含 ReadFile、SearchReplace、Bash、Task 等實現。

grok_build_concise

精簡工具族，目錄中包含 read_file、search_replace 與 bash。

grok_build_hashline

帶 hashline 語義的 read_file、edit 與 grep 實現。

codex

包含 apply_patch、read_file、list_dir、grep_files 等兼容實現。

opencode

包含 read、write、edit、bash、glob、grep、skill 與 todowrite。

memory / lsp / skills

按能力拆出的實現模組。namespace 枚舉還包含 MCP，用於運行時外部工具。

動態 MCP 的兩個穩定入口

SearchTool

在 ToolIndex 中按 BM25 搜索 MCP 工具。結果按 server 分組，並返回工具描述與 input_schema。

query: String關鍵詞
limit: Option<u8>預設 5

UseTool

接收發現後的合格工具名，通過 InnerDispatch 或 managed gateway 調用 MCP。這個固定入口讓模型工具列表跨輪次保持穩定。

tool_name: String通常為 server__tool
tool_input: Value按發現到的 schema 構造

pub struct ToolBridge {
    registry: Arc<FinalizedToolset>,
    terminal: Option<Arc<dyn TerminalBackend>>,
}

pub async fn register_mcp_tools<T>(
    &self,
    mcp_name: String,
    tool: T,
    input_schema: Option<serde_json::Value>,
) -> Result<(), xai_tool_runtime::ToolError> {
    self.registry.register_tool(mcp_name, tool, input_schema)?;
    Ok(())
}

pub struct UseToolInput {
    pub tool_name: String,
    pub tool_input: serde_json::Value,
}

追蹤一次外部工具調用

從模型先調用 search_tool 開始，寫出查詢字段、返回中需要讀取的 schema、隨後傳給 use_tool 的兩個字段，以及最終由哪個橋接類型把結果交回會話。

Takeaway：實現族解決多套工具協議的程式碼組織，registry 負責組合與運行時註冊，ToolBridge 連接會話。動態 MCP 通過 SearchTool 發現 schema，再由 UseTool 按 schema 分發執行。
