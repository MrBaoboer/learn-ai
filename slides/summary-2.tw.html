Part 1 · 上下文 & Prompt
📐
一、上下文 & Prompt 工程
設計 Message List 的核心技能
上下文溢位三策略
桌面有限，精心管理
截斷 簡單，但早期資訊永久丟失，適合短對話工具
摘要壓縮 平衡之選，需額外 LLM 呼叫，適合長期對話
語義檢索 最精準，需向量系統，Token 消耗最優
Prompt 六要素 + 四進階技巧
把 Prompt 當程式碼寫
六要素：角色 + 任務 + 上下文 + 約束 + 示例 + 格式

四進階：Few-Shot（示例學格式）、Chain of Thought（逐步推理）、Constraints（字數/語氣/禁用詞）、Task Decomposition（拆步驟）
輸出格式取捨原則
根據場景選格式
流式展示使用者側 → XML / 純文字（可增量解析）
後端程式消費 → YAML / JSON（YAML 省 15-30% Token）
文件/富文字展示 → Markdown（渲染友好）
Part 2 · Agent 工程
🤖
二、Agent 工程
讓 AI 從"說"到"做"
Agent 四大核心能力
🧭 Plan 規劃
把複雜任務拆解為可執行步驟
🔧 Tool Use
呼叫搜尋、程式碼執行、資料庫、API
🗃️ Memory 記憶
短期上下文 + 長期向量資料庫
🔄 Act / Reflect
執行後觀察，失敗則自我糾錯
工具呼叫的真相
模型只是輸出了格式化文字
1
System Prompt 預定義工具列表，告知模型可用工具
2
模型預測出一段 JSON 文字（不是真呼叫）
3
框架程式碼解析 JSON → 真正呼叫 API → 結果注回上下文
Skill + 腳手架
讓 Agent 可靠執行
Skill = 流程說明 + 工具呼叫指引，讓 ReAct 迴圈儘可能短且高效

腳手架 = 超時/重試 + 最大步數限制 + 輸入輸出驗證 + 狀態機 + 可觀測性（日誌）。
沒有腳手架的 Agent 在生產環境不可靠。
